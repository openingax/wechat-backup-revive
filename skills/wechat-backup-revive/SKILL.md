# 复活旧的微信 4.x 备份

只用于恢复**用户自己账号**的备份。全程不解密、不改加密数据，只调整备份的目录位置和明文登记信息，最后由微信官方客户端自己完成解密和恢复。

## 原理（2026-10 在 Mac 微信 4.1.13 上验证）

旧备份"看不到"，通常要依次过下面几关：

1. **目录结构。** 新版会在用户选择的备份位置下自动加一层，实际查找路径是 `<备份位置>/xwechat_backup/<微信号>/<hash>/files/<N>/`。
2. **`alt_name.dat`。** `<hash>/` 目录里要有这个文件，内容是 `…@ilink.im.iot_user` 用户 ID。没有它，整个目录会被跳过。这个 ID 在本机是加密存放的，无法直接读出。
3. **存储类型。** `pkg_info.dat` 第 4 字段的存储设备类型：4011 表示"这台电脑"，13001 表示手机直接写入的"外部存储设备"。Mac 只列出前者。
4. **服务器核对。** Mac 会把第 8 字段 `unique_package_id` 发给服务器核对，服务器不认识的包会被隐藏。**这是最难过的一关。**
5. **手机端的恢复清单。** 恢复时，手机按自己本地记录的清单决定恢复哪些聊天。本地没有这份记录的设备（例如刚登录的 iPad）会把包里所有会话目录都恢复出来。

加密文件开头是 `RMFH`，文件头第 12 个字节是密钥编号。旧包使用的是同一账号早期的密钥编号，只要服务器还给这些编号的密钥，恢复就能成功。

## 步骤

所有操作都在 APFS 克隆上进行，原件保持不动。先把备份复制到 APFS 格式的盘上；`cp -c` 只在同一个 APFS 卷内才能秒完成，而且不占额外空间。

```bash
W=scripts/wxbackup.py   # 只依赖 Python 3 标准库；可先运行 python3 -I $W selftest 自检
```

1. **体检。** `python3 -I $W inspect <旧备份的 hash 目录>`，检查是否缺 `alt_name.dat`、存储类型（13001 还是 4011）、密钥编号分布。
2. **设置备份位置。** 在 Mac 微信里把备份位置设为目标文件夹 `ROOT`，并登录**做那份备份时用的账号**。ROOT 下会自动生成 `xwechat_backup/<微信号>/`。
3. **克隆就位。** `python3 -I $W stage <旧 hash 目录> ROOT <微信号>`。
4. **获取 `alt_name.dat`。** 让用户用同一账号的手机往这台 Mac 做一份**很小的备份**（只选一个聊天）。微信会把它写进同一个 `<hash>` 目录，并自动生成 `alt_name.dat`。新包的编号记为 `NEW`（例如 `files/5`）。
   - 如果新包写进了另一个 hash 目录，就把那份 `alt_name.dat` 复制到旧目录里。
5. **借用 ID。** `python3 -I $W borrow ROOT/xwechat_backup/<微信号>/<hash> <旧编号> <NEW> ROOT/_hold`。这一步会把真正的新包移到 `_hold`，把旧数据放进 `files/<NEW>`，并换上新包的唯一 ID 和"这台电脑"的存储类型。
6. 让用户按 ⌘Q 退出 Mac 微信再打开。列表里那一项应显示为旧备份的大小和日期。
7. **恢复。**
   - 先做一次小范围试恢复，确认旧密钥可用。手机按本地清单只会恢复新包里那个聊天，如果旧包里也有这个聊天（会话目录名相同），恢复出来的就是旧数据。
   - 全量恢复要用**本地没有这份包记录的设备**，例如刚登录、已清空聊天记录的 iPad。
   - 恢复完成后，可以在该设备上做一次正常的"全部聊天"备份，再恢复到主力手机。
8. **观察进度（可选）。** 先运行 `mark <files/NEW>`，恢复过程中运行 `progress <files/NEW>`，查看已读取的会话目录数和字节数。原理是 macOS 只在 atime ≤ mtime 时才更新 atime。

## 注意

- **不要在克隆目录上开"自动备份"。** 手机会往同一个包里写入，覆盖旧数据。
- 恢复是合并操作，不会删除现有消息。但恢复全部聊天之前，建议先给手机做一次完整备份。
- `.wechat-deviceId`、`un_fin_id.dat`、`d_s.dat` 不影响 Mac 端识别。
- 实测中，iPad 全量恢复读取了 99% 的数据，但跳过了一些很小的会话目录（116 个里有 45 个，合计约 0.2 GB），原因未查明。恢复完成后，可以用 `progress` 列出没被读取的目录，必要时再恢复一次。
- 如果服务器已经不再提供旧编号的密钥，这套方法就恢复不出数据，只能另找办法获取密钥自行解密，这部分不在本 skill 范围内。
